# 章節撰寫守則

以資料結構第 1 章「基本觀念與複雜度」為範本（`src/content/chapters/data-structures/basics.mdx`、`src/content/questions/data-structures/basics/`）。寫新的一章時，先把範本讀一遍，再照這份守則寫。標示 **［自動檢查］** 的規則由 `pnpm test`／`pnpm test:e2e` 檢查，違反時 CI 不會通過。

## 1. 目標

讀者是準備資工所、資管所考試的考生。一章寫完要做到：**讀完觀念說明的人，能自己寫出這一章的考題**。判斷標準不是「內容有沒有提到」，而是「一個第一次讀的人，能不能跟著每一步推下去」。

## 2. 一章的組成

| 部分 | 位置 | 要求 |
|---|---|---|
| 章節資料 | `src/data/subjects.ts` | 單元 3～6 個；章末檢核 4～6 條 **［自動檢查］** |
| 觀念說明 | `src/content/chapters/<科目>/<章節>.mdx` | frontmatter 的 `summary` 一兩句話說這一章考什麼 **［自動檢查］** |
| 考題 | `src/content/questions/<科目>/<章節>/NN.mdx` | 8～12 題，`order` 從 1 連續，每題都有 `<Solution>` **［自動檢查］** |
| 圖 | `src/components/content/figures/` | 每章 3～6 張，放在最需要「看到」才懂的地方 |

**單元與觀念說明的對應**：沒有互動單元頁的單元，觀念說明裡要有一個**同名**的 `###` 段落（章節頁的單元清單會連過去）**［自動檢查］**。段落順序與 `subjects.ts` 的單元順序一致；之後可以多一段 `### 常見陷阱`，**最後一段一定是 `### 專有名詞`**（見 4.4）**［自動檢查］**。

**章末檢核**：每條都是「能……」開頭的具體能力，讀者可以自己判斷做不做得到（「能手算 AVL 插入並指出旋轉類型」，不是「了解 AVL 樹」）。每個單元至少對應一條。

## 3. 寫作原則

### 3.1 先直覺，再定義，再例子

每個新概念依序寫：

1. **為什麼需要它**：它要解決什麼問題（例：換一台電腦常數就變了，所以只看成長率）。
2. **白話的意思**：用一句話說它在表達什麼。
3. **定義**：正式定義放在引用區塊 `> **定義**：……`。
4. **例子**：帶具體數字，一步一步代入。
5. **反例或限制**：什麼情況不成立、什麼時候不能用。

### 3.2 符號第一次出現就說明

任何字母、參數第一次出現，就說明它**代表什麼、為什麼需要它**，之後才可以代入。第 1 章的教訓：先寫「取 c = 15、n₀ = 1」再解釋 c 和 n₀，讀者看不懂。

- ✗ 「取 c = 15、n₀ = 1，因為……」（c、n₀ 還沒說明）
- ✓ 先說「c 是允許的常數倍、n₀ 是從哪裡開始算」，再示範怎麼找出它們

### 3.3 推導不跳步

- 每個證明或計算寫成「**目標 → 想法 → 步驟 → 結論**」。
- 用到的公式要寫出來或給一句理由（等比級數、1 加到 n、換底公式）。代換、移項、取 log 這類動作，每一步單獨一行。
- 「由此可知」「顯然」之前，先問自己：第一次讀的人知道為什麼嗎？不知道就補一步。
- 有多種方法時（展開法、遞迴樹、主定理），各用同一個例子示範，讓讀者能比較。

### 3.4 給讀者「怎麼做」，不只給答案

- 解題方法整理成編號步驟（例：主定理的四個步驟），例子照步驟逐一套用。
- 結果不唯一時要說明（例：c 和 n₀ 不唯一，c 越小 n₀ 通常越大）。
- 「什麼時候不能用」要和「怎麼用」一樣清楚，並附一個實際算出來的例子。

### 3.5 用語與語氣

- 台灣慣用譯名，專有名詞第一次出現時用粗體並附英文原文：**演算法**（algorithm）。這樣引入的名詞都要收進章末的專有名詞表 **［自動檢查］**。
- 直接、具體，不寫「非常重要」「眾所周知」這類空話；一段講一件事。
- 考試常見的陷阱寫進正文對應的位置，章末再整理成 `### 常見陷阱`。

## 4. 格式

### 4.1 標題

- `###`：單元段落（與單元同名）、「常見陷阱」與「專有名詞」。
- `####`：段落內的小標，例如「Big-O：上界」「例：一步一步證明……」。
- 不用 `##`（章節頁的四大段才是 `##`）。

### 4.2 數學式

- 一律用公式元件：行內 `<M t="n^2" />`、獨立一行 `<M d t="..." />`。**不能用 `$…$`**：MDX 會把 `{}` 當成 JavaScript **［自動檢查］**。TeX 寫錯時建置會失敗。
- 變數、函數、複雜度都要用公式元件，連單一個 `n` 也是，讓字形一致。
- 多行推導用 `\begin{aligned} … \end{aligned}` 對齊等號，不要寫成連續的文字行。
- 獨立一行的公式不要太長（手機上會需要橫向捲動）。像定義這種「文字 + 條件」的長句，改寫成句子裡的行內公式。
- 公式裡不放長的中文句子。必要的短註解可以用 `\text{因為 } n \le n^2`。

### 4.3 清單、選項與程式碼

- 正文裡的大括號（例如屬性集合 {sid, name}）要寫成 `\{sid, name\}`：MDX 會把 `{…}` 當成 JavaScript，建置會失敗 **［自動檢查］**。公式元件、圖的 caption 與程式碼區塊裡不用跳脫。
- Markdown 會把**相鄰的兩行合併成一段**。選項 (A)(B)(C)、小題 (a)(b) 之間要空一行 **［自動檢查］**。
- 程式碼區塊是偽代碼（不上色），寫成考卷上常見的樣子：`for i = 1 to n`。
- 表格用在「並列比較」（符號對照、情況對照）；表格內的公式不能含 `|`。

### 4.4 專有名詞表

每章觀念說明的最後一段是 `### 專有名詞`，用一個表整理這一章引入的名詞，讓讀者複習或查詢時不必回頭翻正文：

```
### 專有名詞

| 名詞 | 英文 | 說明 |
|---|---|---|
| 綱要 | schema | 資料庫的結構描述，很少改變 |
```

- 表頭固定是「名詞 | 英文 | 說明」，每格都要填，至少 5 列 **［自動檢查］**。
- 正文中以 `**名詞**（English…）` 引入的名詞，都要出現在「名詞」欄（可以合併成「內涵／外延」這種寫法）**［自動檢查］**。正文沒有附英文、但考試常考的名詞也要收進來。
- 順序跟著正文第一次出現的順序。
- 「說明」一句話、約 25 字以內（手機上三欄並排），寫「它是什麼」，不重複正文的推導；可以用公式元件。同義詞寫在說明裡（「又叫邏輯層」）。

## 5. 圖

### 5.1 什麼時候畫

畫在「文字要繞很多圈才講得清楚、一張圖就懂」的地方：計數（格子、三角形）、定義的幾何意義（曲線何時交叉）、成長的比較、遞迴的結構（遞迴樹）、多種情況的對照（小倍數並排）。一章 3～6 張。

### 5.2 怎麼畫

- 寫成 `src/components/content/figures/` 底下的 Astro 元件，在 `src/components/content/index.ts` 登記，MDX 裡用 `<Figure no="1-2" caption="…"><BigODefinition /></Figure>`。
- **圖號是「章-序號」**，從 1 開始連續（第 2 章是 2-1、2-2……）**［自動檢查］**。正文要提到圖號（「見圖 2-1」）。
- **座標一律由函數或資料計算**，不手寫座標；改函數時圖跟著變。
- 只用墨色：線 2px、軸與刻度是實線髮絲灰、刻度數字等寬 11px。多條曲線以標在線端的名稱區分，必要時加虛線當第二種編碼。不加新顏色（DESIGN.md 只有一個強調色）。
- 圖寬以內容欄為準，**不超過 540px**（內容欄扣掉圖框內距約 551px）；桌機上不能需要橫向捲動 **［自動檢查］**。
- 每張圖有 `role="img"` 與說明重點的 `aria-label`（不是「一張圖」，而是「n 小於 7.4 時 f 比較大，之後……」）。資料圖附「看數值」表格。
- caption 寫「這張圖要看什麼」，一兩句。

## 6. 考題

### 6.1 組成

- 8～12 題，**由易到難**排 `order`。難度大約：1 星 3～4 題、2 星 4～6 題、3 星 1～2 題。
- 題型混合：選擇（含複選）、填充、計算；有證明需求的章節加證明題。
- 涵蓋每個單元，至少一題考「什麼時候不能用／常見陷阱」。
- 沒有出處的是自編題（省略 `source`）。收錄考古題前，先確認 PRODUCT.md 待決事項中的授權問題。

### 6.2 詳解

- 先寫答案（粗體），再寫**怎麼得到**：用了哪個方法、每一步。選擇題的每個選項都要說明對錯的理由。
- 證明 O／Ω 時寫出 c 和 n₀ 是怎麼找到的；說明「不成立」時寫出為什麼找不到。
- 可以引用觀念說明的圖（「見觀念說明的圖 1-4」）。
- 有對應的互動單元時，附「在互動單元中開啟這組資料」的連結（分享連結功能上線後）。

### 6.3 驗算

**每一個數字答案都要用程式驗算過才能寫進詳解**：

- 迴圈次數：寫出同樣的迴圈實際數。
- 遞迴式的精確解：直接遞迴算出前幾十項比對。
- 漸近的答案：算「實際值 ÷ 答案」在 n 越來越大時是否收斂到常數。
- 演算法的手算過程：用 `src/core/` 的 Step Trace 跑同一組資料。

驗算程式不需要 commit，但 PR 描述要列出「驗算了什麼」。**驗算不出乾淨答案的題目就刪掉或改題**（第 1 章曾刪掉「整數除以 3 的迴圈」，因為 n = 2 時公式不成立）。

## 7. 交付前的檢查清單

1. `pnpm check`、`pnpm test`、`pnpm build` 都通過（包含本守則的自動檢查）。
2. `pnpm test:e2e` 通過：有觀念說明的章節會自動做無障礙掃描（含展開的詳解）與橫向溢出檢查。
3. 用瀏覽器實際看過（桌機 1280 與 iPhone 尺寸）：每張圖完整不被切、長公式不溢出、選項與推導沒有被合併成一行。
4. 從頭讀一遍觀念說明，逐段問：「第一次讀的人跟得上嗎？哪個符號還沒說明就用了？」
5. 照 `.claude/skills/ship/SKILL.md` 開 PR，把預覽網址交給使用者確認。
