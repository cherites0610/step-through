### 演算法與效能分析

**演算法**（algorithm）是解決問題的有限步驟。課本常列出它必須滿足的五個性質：

| 性質 | 意思 |
|---|---|
| 輸入（input） | 零個或多個由外部提供的資料 |
| 輸出（output） | 至少產生一個結果 |
| 明確性（definiteness） | 每一步都清楚、沒有歧義 |
| 有限性（finiteness） | 一定會在有限步之後結束 |
| 有效性（effectiveness） | 每一步都基本到可以用紙筆在有限時間內做完 |

「程式」不一定滿足有限性：作業系統本身就是一個不會主動結束的程式，所以它不是演算法。這是選擇題常見的陷阱。

分析一個演算法，看兩件事：

- **時間複雜度**：執行需要多少步，表示成輸入大小 n 的函數。
- **空間複雜度**：除了輸入本身之外，還需要多少額外記憶體（變數、陣列、遞迴呼叫的堆疊）。

考試常要求**步驟計數**：算出某一行敘述被執行幾次。方法是由內往外，把每一層迴圈的次數加總。

```
for i = 1 to n
    for j = i to n
        x = x + 1
```

i = 1 時內層跑 n 次，i = 2 時跑 n − 1 次，……，i = n 時跑 1 次，所以 `x = x + 1` 共執行 n + (n − 1) + … + 1 = **n(n + 1) / 2** 次。

另一種常見的迴圈是「每次乘以 2」：

```
i = 1
while i < n
    i = i * 2
```

i 依序是 1, 2, 4, …，第 k 次檢查時 i = 2^(k−1)。迴圈在 i ≥ n 時停止，所以本體執行 **⌈log₂ n⌉** 次（n ≥ 1）。看到變數被乘或除以常數，答案就跟 log 有關。

### 漸近符號

精確的步驟數（例如 3n² + 5n + 7）太瑣碎，我們只在意 n 很大時的**成長率**。漸近符號就是用來描述成長率的語言：

| 符號 | 定義 | 直覺 |
|---|---|---|
| f(n) = O(g(n)) | 存在常數 c > 0 與 n₀，使所有 n ≥ n₀ 都有 f(n) ≤ c·g(n) | f 的上界，「不會比 g 長得快」 |
| f(n) = Ω(g(n)) | 存在常數 c > 0 與 n₀，使所有 n ≥ n₀ 都有 f(n) ≥ c·g(n) | f 的下界，「至少和 g 一樣快」 |
| f(n) = Θ(g(n)) | 同時 f = O(g) 且 f = Ω(g) | 同一個成長率 |
| f(n) = o(g(n)) | 對**每個** c > 0 都存在 n₀，使 n ≥ n₀ 時 f(n) < c·g(n) | 嚴格比 g 慢，等價於 f(n)/g(n) → 0 |
| f(n) = ω(g(n)) | 對每個 c > 0 都存在 n₀，使 n ≥ n₀ 時 f(n) > c·g(n) | 嚴格比 g 快，等價於 f(n)/g(n) → ∞ |

例：3n² + 5n + 7 = Θ(n²)。取 c = 15、n₀ = 1，因為 n ≥ 1 時 3n² + 5n + 7 ≤ 3n² + 5n² + 7n² = 15n²，所以是 O(n²)；又 3n² + 5n + 7 ≥ 3n²，所以是 Ω(n²)。

常見函數由慢到快的順序（k ≥ 2 是整數、0 < ε < 1）：

1 < log n < log^k n < n^ε < n < n log n < n² < n³ < 2ⁿ < 3ⁿ < n! < nⁿ

幾個比大小時常用的事實：

- **對數的底數不重要**：log₂ n = log₁₀ n / log₁₀ 2，只差一個常數倍，所以 log₂ n = Θ(log₁₀ n)，通常直接寫 log n。
- **指數的底數很重要**：4ⁿ = 2ⁿ·2ⁿ，比 2ⁿ 快得多，4ⁿ ≠ O(2ⁿ)。但 2ⁿ⁺¹ = 2·2ⁿ = Θ(2ⁿ)。
- **任何多項式都贏過任何 log 的次方**：log^k n = o(n^ε)，例如 log¹⁰⁰ n 最後還是比 √n 小。
- **log(n!) = Θ(n log n)**：上界 log(n!) ≤ log(nⁿ) = n log n；下界只看後半段 n/2 個因數，每個至少 n/2，所以 log(n!) ≥ (n/2) log(n/2)。
- **比較兩個函數不知道從何下手時，取 log 再比**：例如 n^(log n) = 2^((log n)²)，而 2ⁿ 的指數是 n，(log n)² 比 n 慢，所以 n^(log n) = o(2ⁿ)。

### 遞迴與遞迴關係式

遞迴程式的時間，可以寫成**遞迴關係式**：T(n) = 「子問題的時間總和」＋「這一層自己做的事」。寫的時候注意三件事：遞迴呼叫了**幾次**、每次的**問題大小**、這一層**額外**做了多少。

| 程式 | 遞迴關係式 | 解 |
|---|---|---|
| 二分搜尋 | T(n) = T(n/2) + Θ(1) | Θ(log n) |
| 合併排序 | T(n) = 2T(n/2) + Θ(n) | Θ(n log n) |
| 河內塔 | T(n) = 2T(n − 1) + 1 | 2ⁿ − 1 |
| 直接遞迴的費氏數列 | T(n) = T(n − 1) + T(n − 2) + Θ(1) | Θ(φⁿ)，φ = (1 + √5)/2 ≈ 1.618 |
| 遞迴求 n! | T(n) = T(n − 1) + Θ(1) | Θ(n) |

解遞迴關係式有三種方法：

**1. 展開（迭代）法**：一直代入，直到看出規律。以河內塔為例，T(1) = 1：

T(n) = 2T(n − 1) + 1 = 4T(n − 2) + 2 + 1 = … = 2^(n−1)·T(1) + 2^(n−2) + … + 2 + 1 = 2ⁿ − 1

**2. 遞迴樹**：把每一層的成本畫出來再加總。以 T(n) = 2T(n/2) + n 為例，第 i 層有 2^i 個子問題、每個大小 n/2^i，所以每層成本都是 n；共 log₂ n 層，總和 Θ(n log n)。

**3. 主定理**：形如 T(n) = aT(n/b) + f(n) 的式子可以直接套用，見下一節。

遞迴也會用到空間：每一層呼叫都佔一格堆疊，所以遞迴的**深度**就是額外空間的下限。直接遞迴的 n! 需要 Θ(n) 的堆疊空間，二分搜尋只需要 Θ(log n)。

### 主定理

對 T(n) = aT(n/b) + f(n)（a ≥ 1、b > 1），把 f(n) 和 **n^(log_b a)** 比大小。n^(log_b a) 是遞迴樹最底層「葉子」的總成本，f(n) 是根節點的成本：

| 情況 | 條件 | 結果 |
|---|---|---|
| 1. 葉子主導 | f(n) = O(n^(log_b a − ε))，ε > 0 | T(n) = Θ(n^(log_b a)) |
| 2. 每層差不多 | f(n) = Θ(n^(log_b a)) | T(n) = Θ(n^(log_b a) · log n) |
| 3. 根主導 | f(n) = Ω(n^(log_b a + ε))，ε > 0，而且 a·f(n/b) ≤ c·f(n)，c < 1 | T(n) = Θ(f(n)) |

情況 2 的**延伸**：若 f(n) = Θ(n^(log_b a) · log^k n)，k ≥ 0，則 T(n) = Θ(n^(log_b a) · log^(k+1) n)。

例：

- T(n) = 9T(n/3) + n：n^(log₃ 9) = n²，f(n) = n 小了多項式倍 → 情況 1，Θ(n²)。
- T(n) = T(2n/3) + 1：a = 1、b = 3/2，n^0 = 1，f(n) = Θ(1) → 情況 2，Θ(log n)。
- T(n) = 3T(n/4) + n log n：n^(log₄ 3) ≈ n^0.793，f(n) 大了多項式倍；而且 3·(n/4)·log(n/4) ≤ (3/4)·n log n → 情況 3，Θ(n log n)。

**主定理不能用的情況**：

- 不是「除以 b」的形式，例如 T(n) = T(n − 1) + n（用展開法：Θ(n²)）。
- f(n) 和 n^(log_b a) 差的不是**多項式**倍。例如 T(n) = 2T(n/2) + n / log n：f(n) 比 n 小，但只小了 log n 倍，不屬於任何一種情況。用遞迴樹算，第 i 層成本是 n / (log n − i)，加總得 Θ(n log log n)。

### 常見陷阱

- **O 不是「剛好」**：n = O(n²) 是對的，只是不夠緊。題目問「最緊的上界」時要寫 Θ 等級的答案。
- **最差情況和平均情況是不同的函數**，各自都可以用 O、Ω、Θ 描述。不要把「O 等於最差、Ω 等於最佳」混為一談。
- **遞迴呼叫兩次和一次差很多**：`return g(n/2) + g(n/2)` 是 2T(n/2)，先算一次再乘 2 只有 T(n/2)。
- **情況 3 要檢查正規條件**（a·f(n/b) ≤ c·f(n)）；考試常見的 f(n) 都滿足，但寫證明題時要寫出來。
