### 基本術語

#### 為什麼要有正式的術語

第 1 章說關聯式模型「把資料表示成表」。日常說「表」就夠了，但考試和教科書用的是一組正式術語，而且這些術語背後有數學定義：表裡能不能有兩列一模一樣？欄位的順序重不重要？一格裡能不能放兩個值？這些問題，要從定義才答得出來。

#### 定義域、屬性與值組

> **定義**：**定義域**（domain）是一組**原子值**（atomic value，不能再拆開的值）的集合，例如「所有 5 碼的學號」「所有系名」。**屬性**（attribute）是某個定義域在關聯中扮演的角色，有自己的名稱。

同一個定義域可以被多個屬性使用：「所有日期」這個定義域，可以同時是生日 birthday 與入學日 enroll_date 的定義域。

> **定義**：**關聯綱要**（relation schema）寫成 <M t="R(A_1, A_2, \ldots, A_n)" />，<M t="R" /> 是關聯的名稱，<M t="A_1" /> 到 <M t="A_n" /> 是屬性。屬性的個數 <M t="n" /> 稱為**分支度**（degree，也叫元數 arity）。

> **定義**：**值組**（tuple）是一組依序排列的值 <M t="\langle v_1, v_2, \ldots, v_n \rangle" />，每個 <M t="v_i" /> 屬於 <M t="A_i" /> 的定義域，或是 NULL。**關聯**（relation）是值組的**集合**，記作 <M t="r(R)" />；值組的個數稱為**基數**（cardinality）。

用集合的語言說：把每個屬性的定義域記作 <M t="\mathrm{dom}(A_i)" />，所有可能的值組就是這些定義域的笛卡兒積（每個定義域各取一個值，所有組合），而一個關聯是其中的一部分：

<M d t="r(R) \subseteq \mathrm{dom}(A_1) \times \mathrm{dom}(A_2) \times \cdots \times \mathrm{dom}(A_n)" />

例如 <M t="\mathrm{dom}(\text{dname}) = \{\text{資管}, \text{資工}, \text{電機}\}" />、<M t="\mathrm{dom}(\text{level}) = \{\text{大學部}, \text{研究所}\}" />，可能的值組共 <M t="3 \times 2 = 6" /> 種；某一時刻的關聯只是其中幾個。

三組術語說的是同一件事，題目可能用任何一組：

| 正式術語 | 表的說法 | 檔案的說法 |
|---|---|---|
| 關聯（relation） | 表（table） | 檔案（file） |
| 值組（tuple） | 列（row） | 紀錄（record） |
| 屬性（attribute） | 欄（column） | 欄位（field） |
| 定義域（domain） | 資料型別 | 欄位的型別 |

#### 關聯的特性

從「關聯是值組的集合」這個定義，可以直接推出四個特性：

1. **值組之間沒有順序**：集合裡的元素沒有先後。把 Student 的列重新排列，還是同一個關聯。
2. **沒有重複的值組**：集合裡同一個元素只出現一次，所以不會有兩列完全相同。
3. **屬性之間的順序不影響意義**：只要每個值都跟著它的屬性名稱，(sid = S1, name = 王小明) 和 (name = 王小明, sid = S1) 是同一個值組。
4. **每一格都是不可再分的值**：因為定義域是原子值的集合，一格裡不能放「一組電話」或「姓和名兩部分」。這就是第 2 章轉綱要時，多值屬性要另開表、複合屬性要拆開的原因，也是第 6 章「第一正規化」的要求。

**關聯式資料庫綱要**（relational database schema）則是一組關聯綱要，加上它們必須遵守的完整性限制（本章第 3 節）。

#### 限制：SQL 的表不完全是關聯

SQL 的表允許有完全相同的兩列（除非宣告了主鍵或 `UNIQUE`），查詢結果也可能有重複。所以嚴格來說，SQL 的表是「可以重複的集合」（多重集合，bag）。第 5 章會看到用 `DISTINCT` 去掉重複。

### 鍵

#### 超鍵

關聯裡沒有重複的值組，所以一定有某些屬性能區分每一個值組。

> **定義**：如果屬性集合 <M t="K" /> 滿足「關聯中任何兩個不同的值組，在 <M t="K" /> 上的值都不完全相同」，<M t="K" /> 就是一個**超鍵**（superkey）。

每個關聯至少有一個超鍵：**全部屬性**合起來一定是超鍵，因為沒有兩個值組完全相同。但超鍵可以帶著多餘的屬性：如果 sid 不重複，\{sid, name\} 也一定不重複，所以也是超鍵。

#### 候選鍵與主鍵

> **定義**：**候選鍵**（candidate key）是**最小**的超鍵：拿掉任何一個屬性之後，就不再是超鍵。從候選鍵中選一個作為**主鍵**（primary key），其餘的候選鍵稱為**替代鍵**（alternate key）。

「最小」的意思是不能再拿掉屬性，**不是**屬性個數最少。判斷一個超鍵是不是候選鍵，就把它的屬性一個一個拿掉，看剩下的還是不是超鍵。

**例**：Student(sid, idno, name, dept)，sid 是學號、idno 是身分證字號，兩者都不會重複。

1. \{sid\}：不重複，是超鍵；只有一個屬性，拿掉就是空集合，所以是候選鍵。
2. \{idno\}：同理，也是候選鍵。
3. \{sid, name\}：是超鍵；拿掉 name 剩 \{sid\} 仍是超鍵，所以**不是**最小，不是候選鍵。
4. 選 sid 當主鍵，idno 就是替代鍵。

由多個屬性組成的鍵稱為**複合鍵**（composite key）。選課 Enroll(sid, cid, grade) 中，sid 會重複（一位學生修很多課）、cid 也會重複（一門課很多學生），但 (sid, cid) 不會重複，而且拿掉任何一個都會重複，所以 \{sid, cid\} 是候選鍵。

#### 數超鍵的個數

考試常問「共有幾個超鍵」。方法：**包含任何一個候選鍵的屬性集合，都是超鍵**，所以只要數「包含某個候選鍵」的子集合有幾個。

**例 1**：<M t="R(A, B, C, D)" />，唯一的候選鍵是 <M t="\{A\}" />。超鍵就是包含 <M t="A" /> 的子集合：<M t="A" /> 一定要選，其餘 <M t="B, C, D" /> 每個可選可不選，共 <M t="2^3 = 8" /> 個。

**例 2**：<M t="R(A, B, C)" />，候選鍵是 <M t="\{A\}" /> 與 <M t="\{B, C\}" />。這時兩類超鍵會重疊，要用排容原理（兩類相加，再扣掉重複算的部分）：

- 包含 <M t="A" /> 的：<M t="B, C" /> 可選可不選，<M t="2^2 = 4" /> 個。
- 包含 <M t="B, C" /> 的：<M t="A" /> 可選可不選，<M t="2^1 = 2" /> 個。
- 兩者都包含（<M t="A, B, C" /> 全選）：<M t="1" /> 個，被算了兩次。

<M d t="4 + 2 - 1 = 5" />

#### 限制：鍵是綱要的性質，不能從資料推出來

鍵說的是「**任何**合法的資料都不會重複」，是設計時依據現實的規則定下的，屬於綱要。眼前這一份資料剛好沒有重複，不代表永遠不會重複：目前全校的學生剛好沒有同名，name 也不能當鍵，因為明天可能就有同名的新生。

反過來卻可以：只要在資料中找到兩個值組在 <M t="K" /> 上相同，就能確定 <M t="K" /> **不是**鍵。所以看著一份資料，只能排除，不能確認。

### 完整性限制

#### 為什麼需要完整性限制

資料庫裡的資料要反映現實：學號不能重複、選課紀錄裡的學生要真的存在、成績要在 0 到 100 之間。這些規則如果交給每支應用程式自己檢查，就回到第 1 章檔案系統的問題。所以把它們寫進綱要，由 DBMS 在每次修改資料時檢查，違反就拒絕。這些規則稱為**完整性限制**（integrity constraint）。

#### 四種完整性限制

| 限制 | 規定 | 例子 |
|---|---|---|
| 定義域限制 | 每個值都屬於該屬性的定義域 | grade 必須是 0 到 100 的整數 |
| 鍵限制 | 任兩個值組的候選鍵值不相同 | 不能有兩位學生的 sid 都是 S1 |
| 實體完整性 | 主鍵的值不能是 NULL | 不能有 sid 是 NULL 的學生 |
| 參考完整性 | 外鍵的值必須在被參照的關聯中存在，或是 NULL | Student 的 dname 必須是 Dept 裡有的系 |

**實體完整性**（entity integrity）為什麼要求主鍵不能是 NULL？主鍵的工作是識別每一個值組；如果兩位學生的 sid 都是 NULL，就分不出他們是誰，外鍵也無法參照到他們。注意它只限制**主鍵**，其他屬性（包括替代鍵）是否可以是 NULL，由設計者另外用 `NOT NULL` 決定。

#### 外鍵與參考完整性

第 2 章轉綱要時已經用過外鍵，這裡給出正式定義：

> **定義**：關聯 <M t="R_1" /> 的屬性集合 <M t="FK" /> 參照關聯 <M t="R_2" /> 的主鍵 <M t="PK" />，如果 <M t="FK" /> 與 <M t="PK" /> 的定義域相同，而且 <M t="R_1" /> 的每一個值組 <M t="t_1" /> 都滿足下列兩者之一，<M t="FK" /> 就是一個**外鍵**（foreign key）：<M t="t_1[FK]" /> 等於 <M t="R_2" /> 中某個值組 <M t="t_2" /> 的 <M t="t_2[PK]" />；或者 <M t="t_1[FK]" /> 是 NULL。這個要求稱為**參考完整性**（referential integrity）。

這裡 <M t="t[X]" /> 表示值組 <M t="t" /> 在屬性 <M t="X" /> 上的值。白話說：外鍵要嘛指向一個真的存在的值組，要嘛是空的（還沒指定）。被參照的 <M t="R_2" /> 也可以就是 <M t="R_1" /> 自己，稱為**自我參照**：Employee(eid, name, boss) 中，boss 是另一位員工的 eid。

#### 例：一步一步檢查一份資料

**目標**：Dept(<u>dname</u>, phone) 目前有「資管」「資工」兩列。要依序新增下列 5 位學生到 Student(<u>sid</u>, name, dname)，dname → Dept，判斷每一列違反哪個限制。

| 列 | sid | name | dname |
|---|---|---|---|
| ① | S1 | 王小明 | 資管 |
| ② | S2 | 李美華 | 電機 |
| ③ | S1 | 陳志強 | 資工 |
| ④ | NULL | 林大同 | 資管 |
| ⑤ | S5 | 黃小華 | NULL |

**想法**：每一列依序檢查四種限制：值在定義域內嗎？主鍵是 NULL 嗎（實體完整性）？主鍵和已經存在的列重複嗎（鍵限制）？外鍵在 Dept 找得到或是 NULL 嗎（參考完整性）？

**步驟**：

1. ① 主鍵 S1 不是 NULL、目前沒有重複；資管在 Dept 中存在。**接受**。
2. ② 主鍵沒問題；但「電機」不在 Dept 中，也不是 NULL。**違反參考完整性**。
3. ③ dname 沒問題；但主鍵 S1 和 ① 重複。**違反鍵限制**。
4. ④ 主鍵是 NULL。**違反實體完整性**。
5. ⑤ 主鍵 S5 沒問題；外鍵是 NULL，參考完整性允許。**接受**（表示這位學生還沒分系；若不允許，要另外加 `NOT NULL`）。

**結論**：只有 ①、⑤ 能存入。

#### 在 SQL 中宣告

這些限制都寫在 `CREATE TABLE` 裡（語法第 5 章詳細介紹）：

```
CREATE TABLE Dept (
    dname  VARCHAR(10) PRIMARY KEY,           -- 鍵限制＋實體完整性
    phone  VARCHAR(12)
);
CREATE TABLE Student (
    sid    CHAR(5)     PRIMARY KEY,
    idno   CHAR(10)    UNIQUE NOT NULL,        -- 替代鍵：不重複、不可空
    name   VARCHAR(20) NOT NULL,
    dname  VARCHAR(10) REFERENCES Dept(dname)  -- 參考完整性
);
CREATE TABLE Enroll (
    sid    CHAR(5) REFERENCES Student(sid),
    cid    CHAR(5),
    grade  INT CHECK (grade BETWEEN 0 AND 100), -- 定義域限制
    PRIMARY KEY (sid, cid)                      -- 複合主鍵
);
```

除了這四種，還有一些和應用有關的規則，例如「一學期最多修 25 學分」，無法用單一欄位的限制表達，稱為**語意限制**（semantic constraint），要用斷言（assertion）、觸發程序（第 5 章）或應用程式檢查。

### 參考完整性的維護

#### 哪些操作會違反哪些限制

資料庫一直在新增、刪除、修改，每一種操作可能違反的限制不同。考試常要求列出這張表：

| 操作 | 可能違反 | 例子 |
|---|---|---|
| 新增 | 四種都可能 | 新增學生時：grade 超出範圍、sid 重複、sid 是 NULL、dname 不存在 |
| 刪除 | **只有**參考完整性 | 刪除 Dept 的「資管」，但還有學生的 dname 是資管 |
| 修改主鍵或外鍵 | 鍵、實體、參考完整性 | 把 Dept 的「資管」改名、把學生的 dname 改成不存在的系 |
| 修改其他屬性 | 只有定義域限制 | 把 phone 改成太長的字串 |

刪除為什麼只會違反參考完整性？刪掉一個值組不會產生新的值，所以不會有值超出定義域、不會產生重複或 NULL 的主鍵；唯一的問題是「別人原本指著它」。而且要注意**方向**：刪除**被參照**的值組（Dept 的資管）才會有問題；刪除**參照別人**的值組（某位學生）不會破壞任何參考。

#### 被參照的值組被刪除時：四種做法

刪除 Dept 的「資管」時，參照它的學生 S1、S3 怎麼辦？定義外鍵時可以指定 DBMS 的處理方式：

| 做法 | SQL | 結果 |
|---|---|---|
| 拒絕 | `ON DELETE RESTRICT`／`NO ACTION`（預設） | 刪除失敗，Dept 與 Student 都不變 |
| 串聯刪除 | `ON DELETE CASCADE` | 一起刪除參照它的學生 S1、S3 |
| 設為空值 | `ON DELETE SET NULL` | S1、S3 的 dname 改為 NULL |
| 設為預設值 | `ON DELETE SET DEFAULT` | S1、S3 的 dname 改為欄位的預設值（例如資工） |

修改被參照的主鍵（例如把「資管」改名為「資訊管理」）有同樣四種做法，寫成 `ON UPDATE CASCADE` 等；CASCADE 會把參照它的外鍵值一起改成新名稱。

#### 例：串聯會一路傳下去

**目標**：Student.dname 是 `ON DELETE CASCADE`，Enroll.sid 也是 `ON DELETE CASCADE`。原本有 3 位學生（S1、S3 是資管，S2 是資工）、4 筆選課（S1 兩筆、S2 一筆、S3 一筆）。刪除 Dept 的「資管」，最後剩幾筆選課？

**步驟**：

1. 刪除 Dept 的資管。
2. Student 中參照資管的 S1、S3 被串聯刪除，剩下 S2。
3. Enroll 中參照 S1、S3 的選課被串聯刪除：S1 的兩筆、S3 的一筆，共 3 筆。

**結論**：4 筆選課只剩 S2 的 1 筆。一個刪除可能透過一連串的 CASCADE 刪掉很多資料，所以 CASCADE 只該用在「主體不在，附屬資料也沒有意義」的地方，例如第 2 章的弱實體（教師刪除時一起刪除眷屬）。

#### 限制：SET NULL 不能用在主鍵的一部分

Enroll 的主鍵是 (sid, cid)，sid 同時是參照 Student 的外鍵。如果設成 `ON DELETE SET NULL`，刪除學生時 sid 會變成 NULL，違反實體完整性，DBMS 會拒絕。所以外鍵是主鍵的一部分時，只能用 RESTRICT 或 CASCADE。

`RESTRICT` 與 `NO ACTION` 在大多數情況下效果相同；差別只在檢查的時機：RESTRICT 立刻檢查，NO ACTION 可以等到整個敘述（或交易）結束才檢查。

### 常見陷阱

- **分支度是屬性的個數，基數是值組的個數**：Student 有 4 個屬性、3 個值組，分支度 4、基數 3。
- **關聯沒有重複的值組、值組之間沒有順序**；SQL 的表則可能有重複的列。
- **候選鍵是「最小」的超鍵**，指不能再拿掉屬性，不是屬性最少；一個關聯可以有好幾個候選鍵，屬性個數也可以不同。
- **從一份資料只能證明某組屬性不是鍵**，不能證明它是鍵。
- **實體完整性只管主鍵**；外鍵可以是 NULL（除非另外宣告 `NOT NULL`）。
- **刪除只可能違反參考完整性**，而且是刪除「被參照」的那一方才會。
- **外鍵是主鍵的一部分時不能 SET NULL**。

| 基數 | cardinality | 關聯中值組的個數 |
| 關聯式資料庫綱要 | relational database schema | 一組關聯綱要加上完整性限制 |
| 多重集合 | bag | 允許重複元素的集合；SQL 的表 |
| 超鍵 | superkey | 能區分每個值組的屬性集合 |
| 候選鍵 | candidate key | 最小的超鍵：拿掉任何屬性就不再是超鍵 |
| 主鍵 | primary key | 選來識別值組的候選鍵 |
| 替代鍵 | alternate key | 沒被選為主鍵的候選鍵 |
| 複合鍵 | composite key | 由多個屬性組成的鍵 |
| 完整性限制 | integrity constraint | 資料必須遵守、由 DBMS 檢查的規則 |
| 定義域限制 | domain constraint | 值必須屬於屬性的定義域 |
| 鍵限制 | key constraint | 任兩個值組的候選鍵值不相同 |
| 實體完整性 | entity integrity | 主鍵不能是 NULL |
| 外鍵 | foreign key | 參照另一個關聯主鍵的屬性集合 |
| 參考完整性 | referential integrity | 外鍵值必須存在於被參照的關聯，或是 NULL |
| 自我參照 | self-referencing | 外鍵參照同一個關聯的主鍵 |
| 語意限制 | semantic constraint | 和應用有關的規則，例如學分上限 |
| 串聯 | cascade | 被參照的值組刪除或修改時，參照它的一起刪除或修改 |
