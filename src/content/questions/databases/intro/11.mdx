圖書館的程式對自己的外部綱要 LibView(sid, name) 下查詢：

```
SELECT name FROM LibView WHERE sid = 'S2';
```

LibView 定義在 Student(sid, name, dept) 之上，Student 的 sid 欄位建有 B+ 樹索引。

(a) 依序說明這個查詢經過三層綱要架構的哪兩個對映，每個對映把查詢翻譯成什麼。

(b) 說明 DBMS 的查詢處理器與儲存管理員在處理這個查詢時，各做了哪些事（至少各舉兩個元件）。

(c) DBA 之後把 sid 上的 B+ 樹索引改成雜湊索引。(a)、(b) 的哪些步驟會改變？圖書館的程式需要修改嗎？

<Solution>

**(a) 先經過外部／概念對映，再經過概念／內部對映。(b) 見下方。(c) 只有概念／內部對映與查詢最佳化器選出的執行計畫改變；程式不必修改（實體資料獨立性）。**

**(a)**

1. **外部／概念對映**：LibView 的 sid、name 來自 Student 的 sid、name，所以查詢被翻譯成概念層的「從 Student 找 sid = S2 的 name」。
2. **概念／內部對映**：Student 存在某個資料檔，sid 上有 B+ 樹索引，所以翻譯成內部層的「沿著 sid 的 B+ 樹找到 S2 的位置，讀出那個磁碟區塊」。

**(b)**

- 查詢處理器：**DML 編譯器**查資料字典，確認 LibView 與欄位存在，展開檢視表的定義；**查詢最佳化器**查資料字典得知 sid 上有索引，比較「掃描整個檔案」與「用索引」的成本，選擇成本低的用索引；**查詢執行引擎**照計畫執行。
- 儲存管理員：**授權管理員**確認圖書館有 LibView 的查詢權限；**緩衝區管理員**把索引節點與資料所在的區塊讀進記憶體（已在記憶體就不必讀）；**檔案管理員**找出這些區塊在磁碟上的位置。

**(c)** 改索引是內部綱要的改變。會改變的只有：

- **概念／內部對映**：Student 的 sid 改由雜湊索引存取。
- **查詢最佳化器的選擇**：改成用雜湊找到 S2 的區塊。

外部／概念對映、概念綱要與外部綱要都不變，圖書館的 SQL 一個字都不用改。這就是實體資料獨立性。

</Solution>
